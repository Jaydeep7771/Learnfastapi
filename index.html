P0.1

Why uv replaces pip, venv, pyenv and poetry

One Rust binary owns interpreters, locking, and execution.

The single-tool workflow

uv init · uv add · uv run
What it is

uv is a Rust-written package and project manager that resolves, downloads and links dependencies into a project-local .venv, and also installs CPython itself. It replaces the pyenv + venv + pip + pip-tools + poetry stack with one binary.

Why it matters

Two failure modes disappear. First, "works on my Mac": uv.lock pins the full transitive graph with hashes, so CI and your laptop resolve byte-identically. Second, wrong-interpreter bugs: you never source activate anything. uv run resolves the environment per invocation, so a stale shell cannot point you at system Python 3.9 and silently break type | syntax.

Speed is the side effect, not the point: a global cache plus hardlinking means a cold install of FastAPI's full stack lands in seconds instead of a minute.

How it works

Each uv add edits pyproject.toml, re-resolves the graph into uv.lock, then syncs .venv to match. uv run CMD performs that sync check first (microseconds when already current), then execs CMD with .venv/bin ahead of PATH.

macOS zshinstall uv (Apple Silicon)
# Homebrew, or the standalone installer — either way, one binary.
brew install uv
uv --version
Mental model shift. Prefix commands with uv run instead of activating anything. uv run python, uv run pytest, uv run fastapi dev. If a tutorial says pip install, translate it to uv add.
P0.2

Initialise the project and add dependencies

Runtime deps, dev deps, and the optional AI extra — kept apart on purpose.

Scaffolding in four commands

--no-package keeps it an app, not a library
What it is

uv init --no-package creates a non-packaged project: a pyproject.toml plus a pinned interpreter, with no build backend and no src/ wheel layout. uv add then writes dependencies into the right table.

Why it matters

A deployable service is not a library. Omitting the build backend means no editable-install step and no import path surprises — app/ is simply a package in the project root.

Splitting runtime vs dev vs ai is a deployment decision: ruff and pytest never ship to production, and the heavy AI stack (chromadb pulls onnxruntime) stays optional so Module 1 installs small and fast.

How it works

uv add X → [project.dependencies]. uv add --dev X → [dependency-groups].dev, installed locally but excluded by uv sync --no-dev. uv add --optional ai X → an extra you opt into with --extra ai.

P0.3

Run it, then prove it from the terminal

Swagger UI for exploring; curl for the things Swagger hides.

uv run fastapi dev and the OpenAPI loop

localhost:8000/docs
What it is

fastapi dev is a thin wrapper over uvicorn --reload that finds your FastAPI() instance by import string. /docs is Swagger UI rendered from the OpenAPI schema FastAPI generates out of your type hints.

Why it matters

The schema is derived, not maintained. Your Pydantic models and signatures are the single source of truth, so docs cannot drift from behaviour — the classic rot of hand-written API docs.

Reach for curl anyway: Swagger normalises away raw headers, buffers streaming responses, and hides exactly what you need to see for SSE and for the concurrency lab.

How it works

Reload uses a filesystem watcher: on save, the worker process is killed and re-imported. That means module-level state is lost on every edit — one more reason resources belong in lifespan, not globals.

P0.4

Project structure that survives growth

Layer by responsibility, and let imports only ever point downward.

routers / schemas / models / services / core

the dependency rule
What it is

Five layers with one job each: routers/ speaks HTTP, schemas/ defines the wire contract, services/ holds business logic, models/ maps the database, core/ owns cross-cutting concerns (config, security, errors, middleware). dependencies.py is the wiring.

Why it matters

The rule that earns its keep: imports point downward only. Routers import services; services never import routers. So business logic has no idea HTTP exists and is directly unit-testable, and swapping SQLite for Postgres touches models/ and core/config.py and nothing else.

It also kills circular imports — the most common way a growing FastAPI app becomes unrefactorable.

How it works

Each router is an APIRouter(prefix=…, tags=[…]) that main.py mounts with include_router. The prefix lives with the router, so a route never has to know where it is mounted.

M1.1

Pydantic v2: validation, serialization, and the leak firewall

Separate input, output and storage models — or leak a password hash.

Three models per resource

app/schemas/user.py · app/schemas/item.py
What it is

Pydantic v2 compiles your annotations into a Rust validator (pydantic-core) that coerces and checks every request body, and a serializer that builds every response. response_model runs that serializer on whatever the route returns.

Why it matters

The failure mode it prevents is a data leak. Return an ORM User through response_model=UserRead and only the fields declared on UserRead are serialized. hashed_password is not declared, so it cannot escape — even though the object in memory carries it. Reuse one model for DB and API and the next column you add (stripe_customer_id, internal_notes) ships to clients silently.

Validation also runs at the edge, so your service layer never defends against None, negative prices or 10 MB strings. And v2's validation core is native code: it is typically an order of magnitude faster than v1, which matters once bodies get large.

How it works

Annotated[str, Field(min_length=2)] becomes a reusable type and an OpenAPI constraint. field_validator hooks custom rules. ConfigDict(from_attributes=True) lets the serializer read ORM attributes. computed_field adds derived output that was never stored.

pythonapp/schemas/user.py
from typing import Annotated, Literal
from pydantic import BaseModel, ConfigDict, EmailStr, Field, field_validator

Password = Annotated[str, Field(min_length=10, max_length=128)]

class UserCreate(BaseModel):
    """INPUT only. Accepts a raw password no output schema can echo."""
    email: EmailStr
    password: Password
    role: Literal["user", "admin"] = "user"

    @field_validator("password")
    @classmethod
    def password_strength(cls, v: str) -> str:
        if v.lower() == v or v.upper() == v:
            raise ValueError("password must mix upper and lower case")
        if not any(c.isdigit() for c in v):
            raise ValueError("password must contain a digit")
        return v

class UserRead(BaseModel):
    """OUTPUT only. hashed_password is undeclared -> structurally unleakable."""
    model_config = ConfigDict(from_attributes=True)   # read ORM attributes
    id: int
    email: EmailStr
    role: str
    created_at: datetime
pythonapp/schemas/item.py — PATCH semantics & derived output
PriceCents = Annotated[int, Field(ge=0, le=10_000_00)]

class ItemUpdate(BaseModel):
    """Every field optional. Pair with model_dump(exclude_unset=True) so that
    "field absent" and "field explicitly set to null" stay different things."""
    name: Name | None = None
    description: str | None = Field(default=None, max_length=2000)
    price_cents: PriceCents | None = None

class ItemRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int; name: str; price_cents: int; owner_id: int

    @computed_field            # serialized, never stored, shows up in OpenAPI
    @property
    def price_display(self) -> str:
        return f"${self.price_cents / 100:,.2f}"

class Page[T: BaseModel](BaseModel):
    """Generic envelope: every list endpoint paginates identically."""
    items: list[T]; total: int; limit: int; offset: int
Money is an integer. price_cents: int, never float. Binary floats cannot represent 0.10, so float money accumulates rounding error the moment you sum a cart. Store the smallest unit; format at the edge with computed_field.

M1.2

Dependency injection with Depends

A typed graph resolved per request — and overridable in tests.

Composition, caching, and yield teardown

app/dependencies.py · app/db/session.py
What it is

Depends(fn) declares that a route needs whatever fn returns. FastAPI inspects the signature, builds a graph of sub-dependencies, resolves it before calling your handler, and runs teardown afterwards.

Why it matters

Versus a service locator (get_db() called inside the function) you gain three things. Declared: the graph is in the signature, so the type checker and OpenAPI both see it — a Depends(oauth2_scheme) is what puts the padlock in /docs. Cached: each dependency resolves once per request, so require_role("admin") layered on get_current_user does not re-decode the JWT or re-query the user. Substitutable: app.dependency_overrides[get_session] = fake replaces a node for tests with no monkeypatching.

The yield form prevents the classic connection leak: teardown runs even when the handler raises, so an exception mid-request rolls back and returns the connection to the pool instead of pinning it until timeout.

How it works

Dependencies with yield are wrapped in an AsyncExitStack tied to the request. Code before yield runs on the way in; code after runs on the way out, in reverse order. Sync dependencies are pushed to the AnyIO threadpool, exactly like sync routes.

pythonapp/db/session.py — the yield lifecycle
SessionFactory = async_sessionmaker(
    engine,
    expire_on_commit=False,   # attributes stay readable after commit — no lazy IO
    class_=AsyncSession,         # during response serialization
)

async def get_session() -> AsyncIterator[AsyncSession]:
    async with SessionFactory() as session:
        try:
            yield session          # ← the route body runs here
            await session.commit()  # happy path: one transaction per request
        except Exception:
            await session.rollback()  # runs even on HTTPException
            raise
pythonapp/dependencies.py — aliases, class deps, factories
SessionDep = Annotated[AsyncSession, Depends(get_session)]
TokenDep   = Annotated[str, Depends(oauth2_scheme)]

class Pagination:
    """A CLASS dependency: query params validated once, reused on every list route."""
    def __init__(self,
                 limit: Annotated[int, Query(ge=1, le=100)] = 20,
                 offset: Annotated[int, Query(ge=0)] = 0) -> None:
        self.limit, self.offset = limit, offset

async def get_current_user(token: TokenDep, session: SessionDep) -> User:
    try:
        payload = decode_token(token, expect="access")
    except jwt.PyJWTError as exc:
        raise credentials_error from exc
    user = await session.scalar(select(User).where(User.email == payload["sub"]))
    if user is None: raise credentials_error
    return user

CurrentUser = Annotated[User, Depends(get_current_user)]

def require_role(*roles: str):
    """A FACTORY: returns a guard closed over the allowed roles.
    It builds on CurrentUser, which FastAPI still resolves only once."""
    def guard(user: CurrentUser) -> User:
        if user.role not in roles:
            raise HTTPException(403, f"requires one of roles: {roles}")
        return user
    return guard

AdminUser = Annotated[User, Depends(require_role("admin"))]
Annotated aliases are the payoff. Once SessionDep and CurrentUser exist, a protected route signature reads async def delete(item_id: int, session: SessionDep, user: AdminUser) — fully typed, self-documenting, and the authorisation is impossible to forget because it is a parameter.

Async CRUD with SQLAlchemy 2.0

AsyncSession, keyset-friendly pagination, and honest PATCH.

Create · Read+filter · PATCH · Delete

app/services/items.py · app/routers/items.py
What it is

SQLAlchemy 2.0's unified API: build a select() statement, hand it to an AsyncSession, await the result. aiosqlite runs SQLite calls on a background thread so they look awaitable, giving you Postgres-shaped code with a zero-config file database.

Why it matters

Three traps this layout avoids. Lazy-load after commit: with the default expire_on_commit=True, touching item.name during response serialization triggers a fresh SELECT — and in async context that raises MissingGreenlet. We set it to False.

Unbounded lists: a GET /items with no limit is a latent outage the day the table hits a million rows. Pagination caps it at 100 by the type system.

PUT-shaped PATCH: dumping the whole model on update silently nulls every field the client omitted. exclude_unset=True is the fix.

How it works

One transaction per request, owned by the get_session dependency. Services call flush() — which emits the SQL and populates the primary key without ending the transaction — and let the dependency commit. A failure anywhere rolls the whole request back atomically.

pythonapp/models/item.py — typed mappers
class Item(Base):
    __tablename__ = "items"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(120), index=True)
    description: Mapped[str | None] = mapped_column(Text, default=None)
    price_cents: Mapped[int] = mapped_column(Integer, default=0)
    owner_id: Mapped[int] = mapped_column(
        ForeignKey("users.id", ondelete="CASCADE"), index=True)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now())   # DB clock, not app clock
pythonapp/services/items.py — filtering, counting, patching
async def list_items(session, *, limit, offset, owner_id=None, q=None, min_price=None):
    stmt = select(Item)
    if owner_id is not None: stmt = stmt.where(Item.owner_id == owner_id)
    if q:                   stmt = stmt.where(Item.name.ilike(f"%{q}%"))
    if min_price is not None: stmt = stmt.where(Item.price_cents >= min_price)

    # total over the SAME filters, so the client can size the pager
    total = await session.scalar(select(func.count()).select_from(stmt.subquery()))
    rows  = await session.scalars(stmt.order_by(Item.id.desc()).limit(limit).offset(offset))
    return list(rows), int(total or 0)

async def update_item(session, item_id: int, payload: ItemUpdate) -> Item:
    item = await get_item(session, item_id)        # raises AppError(404)
    # exclude_unset -> a body of {"price_cents": 0} touches ONLY the price
    for field, value in payload.model_dump(exclude_unset=True).items():
        setattr(item, field, value)
    await session.flush()                         # emit UPDATE, keep the txn open
    await session.refresh(item)                   # pick up onupdate=func.now()
    return item
pythonapp/routers/items.py — the router stays thin

M1.4

Authentication & RBAC

Argon2 hashes, short access tokens, long refresh tokens, one role guard.

OAuth2 password bearer, end to end

app/core/security.py · app/routers/auth.py
What it is

Passwords are hashed with Argon2id via pwdlib. A successful login returns two JWTs: a short-lived access token carrying sub and role, and a long-lived refresh token that can only mint new access tokens. require_role() enforces authorisation.

Why it matters

Argon2id over bcrypt/SHA: it is memory-hard. SHA-256 is designed to be fast, so a leaked table falls to billions of GPU guesses per second. Argon2id forces each guess to allocate tens of megabytes, collapsing GPU parallelism. It also has no 72-byte truncation surprise.

Two token lifetimes resolve a real tension: JWTs are stateless, so you cannot un-issue one. A 15-minute access token bounds the damage of theft; the refresh token lives in storage you can revoke. Skip the split and you choose between re-login every 15 minutes and a stolen token that works for a week.

The typ claim closes a confusion attack: without it, a refresh token is a valid access token, undoing the whole design.

How it works

OAuth2PasswordBearer(tokenUrl="/auth/login") extracts the Authorization: Bearer header and drives the Authorize button in /docs. jwt.decode verifies the HMAC signature and exp; we then assert typ and load the user. Login returns one identical error for unknown-email and wrong-password so response differences cannot enumerate accounts.

pythonapp/core/security.py
from pwdlib import PasswordHash
import jwt

# Argon2id with sane params baked into the hash string (salt included).
_password_hash = PasswordHash.recommended()

def hash_password(raw: str) -> str:        return _password_hash.hash(raw)
def verify_password(raw, hashed) -> bool:  return _password_hash.verify(raw, hashed)

def _create_token(subject, token_type, expires, extra=None) -> str:
    now = datetime.now(UTC)
    payload = {
        "sub": subject,
        "typ": token_type,              # ← blocks refresh-as-access confusion
        "iat": int(now.timestamp()),
        "exp": int((now + expires).timestamp()),
        "jti": uuid4().hex,             # unique id → a denylist can revoke one token
        **(extra or {}),
    }
    return jwt.encode(payload, s.jwt_secret, algorithm=s.jwt_algorithm)

def decode_token(token: str, *, expect: TokenType) -> dict:
    payload = jwt.decode(token, s.jwt_secret, algorithms=[s.jwt_algorithm])  # verifies exp too
    if payload.get("typ") != expect:
        raise jwt.InvalidTokenError(f"expected a {expect} token")
    return payload
pythonapp/routers/auth.py — login & the guarded route
@router.post("/login", response_model=TokenPair)
async def login(form: Annotated[OAuth2PasswordRequestForm, Depends()], session: SessionDep):
    user = await session.scalar(select(User).where(User.email == form.username))

                            headers={"WWW-Authenticate": "Bearer"})
    return _issue(user)

@router.get("/admin-only", response_model=UserRead)

M1.5

Async vs multi-threading vs multiprocessing

One event loop thread. Everything here follows from that.

Where your code actually runs

app/routers/concurrency.py · app/services/heavy.py
What it is

Uvicorn runs one asyncio event loop on one thread per worker process. An async def route executes on that thread. A plain def route is pushed by FastAPI to AnyIO's worker threadpool (40 threads by default). CPU-bound work belongs in neither — it needs a separate process.

Why it matters

This single fact explains the most common production outage in FastAPI apps: one blocking call inside one async def freezes the entire worker. Not that route — every route, including /health, because they all share the thread. Latency does not degrade gracefully; it cliff-edges.

And threads only fix I/O. CPU-bound Python holds the GIL, so moving a hash loop into a thread buys you nothing: ten concurrent requests still take ten times as long. That is what the process pool is for — and why it is not free, since arguments must be pickled across a process boundary.

How it works

await on real I/O yields control back to the loop, which runs other tasks until the OS says the socket is ready. A blocking call never yields, so the loop has no opportunity to schedule anything. asyncio.to_thread() hands one call to a thread; loop.run_in_executor(pool, …) hands it to a process.

Middleware, global error handling & lifespan

The onion around every request, and the resources it borrows.

Correlation IDs, RFC 9457, and startup pools

app/core/middleware.py · problems.py · main.py
What it is

Middleware wraps every request on the way in and the response on the way out. Exception handlers convert raised exceptions into responses. lifespan is an @asynccontextmanager that runs once at startup and once at shutdown.

Why it matters

Correlation IDs make a distributed system debuggable: one id, generated or accepted from the edge, appears in every log line and in the error body a user can read back to you. Without it you are grepping timestamps.

RFC 9457 Problem Details gives errors one machine-readable shape — type, title, status, detail, instance — so clients branch on a stable field instead of regexing prose. The catch-all handler is also a security control: it guarantees no stack trace or SQL ever reaches a client.

Lifespan fixes resource lifetime. An httpx.AsyncClient created per request throws away connection pooling and TLS reuse and leaks sockets under load. Created once in lifespan, it is shared and closed deterministically on SIGTERM.

How it works

Middleware is LIFO: the last added is outermost. Ours is written as pure ASGI rather than BaseHTTPMiddleware, because the latter pipes responses through an anyio memory stream, which adds a task hop and can buffer a StreamingResponse — fatal for the SSE endpoints in Module 2.

pythonapp/core/middleware.py — pure ASGI
class CorrelationTimingMiddleware:
    def __init__(self, app): self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":                  # let lifespan/websocket pass through
            return await self.app(scope, receive, send)

        incoming = dict(scope["headers"]).get(b"x-correlation-id")
        cid = incoming.decode() if incoming else uuid.uuid4().hex   # trust the edge, else mint
        scope.setdefault("state", {})["correlation_id"] = cid
        started = time.perf_counter()

        async def send_wrapper(message):
            if message["type"] == "http.response.start":   # headers only — body untouched,
                ms = (time.perf_counter() - started) * 1000  # so streaming still streams
                message["headers"].append((b"x-correlation-id", cid.encode()))
                message["headers"].append((b"x-process-time-ms", f"{ms:.2f}".encode()))
            await send(message)

        await self.app(scope, receive, send_wrapper)

Streaming LLM tokens with SSE

Trade total latency for time-to-first-token.

StreamingResponse over text/event-stream

app/routers/ai.py · app/services/llm.py
What it is

Server-Sent Events is a one-way text protocol over plain HTTP: the response never ends, and each frame is event: name + data: payload + a blank line. FastAPI streams it by consuming an async generator through StreamingResponse.

Why it matters

A 400-token answer takes ~8 seconds to generate. Buffered, the user stares at a spinner for 8 seconds; streamed, text appears in ~300 ms. Same total time, completely different product — and it also removes gateway idle-timeout failures on long generations.

Why SSE and not WebSockets: you only need server→client. SSE is ordinary HTTP, so your existing auth headers, proxies, load balancers and logging all work unchanged, and browsers reconnect automatically. WebSockets buy bidirectionality you are not using, at the cost of a different protocol to operate.

How it works

Three things must all hold or it silently buffers: (1) an async generator that yields per token — never build the string first; (2) media_type="text/event-stream"; (3) X-Accel-Buffering: no so nginx does not re-buffer. Add a request.is_disconnected() check to stop paying for tokens when the user closes the tab.

pythonapp/routers/ai.py — the SSE endpoint
def sse(event: str, data: dict | str) -> str:
    payload = data if isinstance(data, str) else json.dumps(data)
    # The trailing BLANK LINE terminates the frame. Omit it and EventSource
    # buffers forever — the #1 reason "streaming doesn't work".
    return f"event: {event}\ndata: {payload}\n\n"

@router.post("/ai/stream")
async def stream_chat(payload: ChatRequest, request: Request) -> StreamingResponse:
    async def gen() -> AsyncIterator[str]:
        yield sse("start", {"model": get_settings().chat_model})
        try:
            async for token in astream_tokens(payload.prompt):
                if await request.is_disconnected():
                    break                      # tab closed → stop burning tokens
                yield sse("token", {"t": token})
            yield sse("done", {"ok": True})
        except Exception as exc:
            # Headers already sent: you CANNOT change the status code now.
            yield sse("error", {"message": str(exc)})

    return StreamingResponse(gen(), media_type="text/event-stream",
        headers={"Cache-Control": "no-cache",
                 "Connection": "keep-alive",
                 "X-Accel-Buffering": "no"})   # tell nginx not to re-buffer

M2.2

Retrieval-Augmented Generation

Chunk, embed, retrieve, ground, cite.

Ingestion and query, with the trade-offs made explicit

app/services/rag.py · POST /rag/ingest · POST /rag/query
What it is

Two pipelines. Ingest: extract text → split into overlapping chunks → embed each chunk into a vector → persist in ChromaDB under ./chroma_data. Query: embed the question, find the nearest chunks by cosine similarity, paste them into a grounded prompt, and return the answer with citations.

Why it matters

RAG attacks two LLM failure modes at once: it supplies knowledge the model never trained on (your documents), and it makes answers auditable — a citation is a claim the reader can check. The prompt's instruction to reply "Not in the provided sources" is what converts a confident hallucination into an honest miss.

Chunk size is the central trade-off. Too large and the embedding averages several topics into a vague centroid that matches everything weakly; you also burn context on irrelevant text. Too small and each chunk loses the context that made it meaningful — a chunk saying "it must be rotated every 90 days" is useless if "the signing key" sat in the previous chunk. ~800 characters with ~120 of overlap is a sane default: the overlap is insurance against a cut landing mid-argument.

Cosine similarity compares direction, not magnitude, so a long document chunk and a short question are comparable. It is also only lexical-semantic closeness — not relevance. A chunk that mentions all your keywords while answering a different question still scores highly, which is why production systems add reranking and a score floor.

How it works

RecursiveCharacterTextSplitter tries separators in order — paragraph, line, sentence, word — so splits land on natural boundaries rather than mid-word. Chroma persists vectors plus metadata to disk; the metadata (source, chunk) is what makes citations possible. PDF parsing and splitting are CPU-bound, so both run through asyncio.to_thread.

pythonapp/services/rag.py — chunking with overlap
CHUNK_SIZE, CHUNK_OVERLAP = 800, 120

def split_text(text: str, size=CHUNK_SIZE, overlap=CHUNK_OVERLAP) -> list[str]:
    from langchain_text_splitters import RecursiveCharacterTextSplitter
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=size,
        chunk_overlap=overlap,
        # Tried in order: paragraph → line → sentence → word → character.
        # Splits land on structure, so a chunk is rarely cut mid-thought.
        separators=["\n\n", "\n", ". ", " ", ""],
    )
    return [c for c in splitter.split_text(text) if c.strip()]

Agentic workflow with LangGraph

A state machine with cycles — not a chain.

Router → Tool → Synthesizer, with an execution trace

app/services/agent_graph.py · POST /agent/chat
What it is

A StateGraph over a TypedDict. Nodes are plain async functions that take the state and return a partial update; edges decide what runs next. A conditional edge reads the state and picks the next node, so the router's decision — tool or straight to synthesis — is data, not control flow buried in an if.

Why it matters

Why a cyclic graph beats a linear chain. A chain is a fixed pipeline: A → B → C, decided before it runs. Real tool use needs a loop: call a tool, look at the result, decide whether it was enough, maybe call another, then answer. In a chain you emulate that with nested conditionals and recursion, and you lose the thread. In a graph, "tool results flow back into the planner" is one edge, and a step budget is a built-in guard rather than a hand-rolled recursion limit.

Why explicit state beats hidden memory. Every transition is a visible merge into one dict, so you can log it, replay it, checkpoint it, and resume mid-run after a crash. The trace channel this graph returns — which nodes ran, which tool, why, how many milliseconds — is the difference between an agent you can debug and a black box you restart.

How it works

Each channel of the state gets a reducer. A scalar like answer is overwritten; trace is annotated with an append reducer, so every node contributes without clobbering the others — the same mechanism that accumulates message history in chat agents. add_conditional_edges("router", route_decision, {...}) maps the function's return value to the next node. compile() validates the graph once at import; ainvoke() runs it.

pythonapp/services/agent_graph.py — state & reducers
def _append(left: list, right: list) -> list:
    return (left or []) + (right or [])

class AgentState(TypedDict, total=False):
    question: str
    route: Literal["tool", "direct"]     # scalars: last write wins
    reason: str
    tool_name: str | None
    tool_output: list[dict]
    answer: str
    trace: Annotated[list[dict], _append]  # ← reducer: nodes APPEND, never overwrite
pythonnodes return partial state — that is the whole contract
async def router_node(state: AgentState) -> AgentState:
    """Deterministic heuristic here so the decision is inspectable. Swap in a
    structured-output LLM call and nothing downstream changes."""
    q = state["question"].lower()
    if any(h in q for h in STATUS_HINTS):
        route, tool, why = "tool", "service_status", "asks about live service state"
    elif any(h in q for h in RETRIEVAL_HINTS) or len(q.split()) > 6:
        route, tool, why = "tool", "vector_search", "likely needs grounded evidence"
    else:
        route, tool, why = "direct", None, "short conversational turn"
    return {"route": route, "tool_name": tool, "reason": why,
            "trace": [{"node": "router", "decision": route, "tool": tool, "why": why}]}

async def tool_node(state: AgentState) -> AgentState:
    name = state.get("tool_name") or "vector_search"
    output = await TOOLS[name](state["question"])
    return {"tool_output": output,
            "trace": [{"node": "tool", "tool": name, "results": len(output)}]}

def route_decision(state: AgentState) -> Literal["tool", "synthesize"]:
    """The conditional edge: the planner's choice, read back out of state."""
    return "tool" if state.get("route") == "tool" else "synthesize"
